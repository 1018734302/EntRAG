# 04 · 踩坑与排障实录

> 本文记录本项目**实际遇到并修复**的问题。每个都写了「现象 → 根因 → 解法」。
> 排障的核心方法论：**不要猜，去拿真实错误**（服务端日志、给数据打时间戳）。

## 通用排障方法论

1. **异常被吞了就去查服务端日志** —— 业务代码只存 `e.getMessage()` 时，真正原因往往在数据库/依赖方的日志里
2. **怀疑流式/时序问题就打时间戳** —— 一眼区分"真流式"和"被缓冲"
3. **浏览器能通 vs 命令行能通，差异往往在请求头** —— 例如浏览器同源 POST 必带 `Origin`

## 二、向量库（pgvector）—— 最难查的一组

### 7. `vector_store` 表"神秘不存在"

- **现象**：应用启动无报错，但表就是没有；上传后入库 `FAILED`
- **根因**：**HNSW 索引维度硬上限 2000 维**，而 `qwen3-embedding:4b` 是 **2560 维** → 建索引失败 → 整段建表语句回滚
- **解法**：`index-type: NONE`（先走精确检索）

```yaml
spring.ai.vectorstore.pgvector:
  index-type: NONE      # 2560 维超过 pgvector HNSW 的 2000 维上限
  dimensions: 2560
```

> 💡 这是**选型期就该确认**的硬约束：先确认嵌入模型维度，再决定索引类型。

### 8. INSERT 报 `bad SQL grammar`（metadata 类型不匹配）

- **现象**：`INSERT INTO vector_store (..., metadata, ...) VALUES (?, ?, ?::jsonb, ?)`
- **根因**：PgVectorStore 的 SQL 里写的是 `?::jsonb`，但表列的 `metadata` 被建成 `json`
- **解法**：`ALTER TABLE vector_store ALTER COLUMN metadata TYPE jsonb`

### 9. INSERT 报 `column "id" is of type uuid but expression is of type character varying`

- **现象**：同上，但换成 id 类型不匹配
- **根因**：PgVectorStore 实际把 id 以 **varchar 字符串**绑定，而我之前把列建成了 `uuid`
- **解法**：`ALTER TABLE vector_store ALTER COLUMN id TYPE text`

> 8 和 9 的真实错误都不是后端日志里那句"bad SQL grammar"（Spring 只给了 SQL 文本，没给下层 cause）。
> **真正原因是从 PostgreSQL 容器日志拿到的**：`docker logs entrag-postgres-1`。
> 教训：`IngestProcessor` 的 catch 只存 `e.getMessage()` 且不打印堆栈，排障时应先加日志或直接查数据库服务端日志。

### 10. `Invalid UUID string: kb2-doc2-c0`

- **现象**：入库 FAILED，`doc_meta.error` 明确报这个
- **根因**：原代码 chunk id 是 `"kb{kb}-doc{doc}-c{i}"` 这类**非 UUID 字符串**，而 PgVectorStore 默认 `idType=UUID` 会做 `UUID.fromString`
- **解法**：改为**确定性 UUID**

```java
private String buildChunkId(Long kbId, Long docId, int index) {
    String raw = "kb" + kbId + "-doc" + docId + "-c" + index;
    return UUID.nameUUIDFromBytes(raw.getBytes(StandardCharsets.UTF_8)).toString();
}
```

用 `nameUUIDFromBytes` 而非随机 UUID，是为了**删除时能重建出同样的 id**。
> 注：`id-type: TEXT` 配置项在本版本未生效，因此走代码层修复。

## 三、前后端联调

### 11. 浏览器登录报"网络请求失败"，但命令行一切正常 ⭐

- **现象**：curl / PowerShell 调登录返回 `code: 0`，浏览器却一直失败
- **关键差异**：**浏览器的同源 POST 一定带 `Origin` 头**，而命令行工具默认不带
- **根因**：后端 CORS 非法组合

```
java.lang.IllegalArgumentException:
When allowCredentials is true, allowedOrigins cannot contain the special value "*"
```

`run-backend.bat` 里 `set RAG_CORS_ALLOWED_ORIGINS=*`，配到 `allowedOrigins("*") + allowCredentials(true)` → Spring 直接抛异常 → **带 Origin 的请求全部 500**。

- **解法**：
  1. `SecurityConfig` 改用 `setAllowedOriginPatterns`（`*` 与 credentials 可共存）
  2. `run-backend.bat` 把 `*` 换成显式来源 `http://localhost:5173,http://127.0.0.1:5173`

> 为什么前端显示"网络请求失败"？Spring 默认 500 响应体**没有 `message` 字段**，
> 拦截器 `err.response?.data?.message || '网络请求失败'` 取不到值，回退成了兜底文案。

### 12. 点登录按钮完全没反应（无提示、不跳转）⭐

- **现象**：静默失败
- **根因**：前端 `api/http.ts` **多解了一层响应**

```ts
// 响应拦截器已经把 AxiosResponse 解包成 body
http.interceptors.response.use((res) => res.data, ...)

// 业务代码却又解了两次 → undefined
const r = await http.post<ApiResult<AuthResponse>>('/auth/login', ...)
return r.data.data      // ❌ 应为 r.data
```

`login()` 返回 `undefined` → `token.value = res.token` 抛 `TypeError` → 被 `Login.vue` 的空 `catch {}` 静默吞掉。
**TypeScript 泛型掩盖了这个问题**（`http.post<T>` 让 `r.data.data` 看起来合法，编译零报错）。

- **解法**：全部改为 `r.data`（共 8 处，影响所有接口）

### 13. 前端查入库状态 404

- **根因**：前端调 `/api/ingest/status/{taskId}`，后端实际是 `/api/kb/ingest/status/{taskId}`（Controller 有 `@RequestMapping("/kb")`）
- **解法**：前端补上 `/kb` 前缀

## 四、流式渲染

### 14. 后端在流式、前端却一次性显示 ⭐⭐（最隐蔽）

- **现象**：时间戳实测证明后端 token 间隔 4~8ms 逐个发，代理也不缓冲，但界面是一下子蹦出整段
- **根因**：**Vue 3 响应式陷阱**

```ts
const ai: ChatMessage = { role: 'ai', content: '' }   // 普通对象
session.messages.push(ai)
...
onToken: (t) => { ai.content += t }                    // 改的是原始对象
```

Vue 3 把对象 `push` 进响应式数组时**不会立刻转代理**，只在读取时惰性包装。
模板读的是代理上的 `content`，而 `onToken` 改的是**原始对象** → **不触发更新**。
token 一直累积，直到 `onDone` 里 `streaming.value = false` 触发一次重渲染 → 整段一次性出现。

- **解法**：

```ts
const ai = reactive<ChatMessage>({ role: 'ai', content: '' })
```

### 15. 首个 token 延迟好几秒 / 答案混入推理文字

- **现象**：提问后空白数秒，然后答案里夹着模型的推理过程
- **根因**：`qwen3` 是**推理模型**，会先思考再作答；且 Spring AI 1.0.0 的 `OllamaOptions` **没有 `think` 选项**（只有 model/topK/temperature）
- **解法**：在 system 提示末尾追加 `<arg_key:6124c78e>`

> 另一个延迟来源是 **Ollama 冷启动**（模型空闲后首次调用要加载，约 4 秒）。
> 判别方法：连续调用两次，若第二次间隔骤降到 ~0.01s，即为冷启动而非思考。

### 16. SSE 结束后后端刷 `Access Denied` 500

- **现象**：`AuthorizationDeniedException` 发生在 `CoyoteAdapter.asyncDispatch`
- **根因**：Spring Security 默认对 **ASYNC 分发二次鉴权**，而 SecurityContext 未传播
- **解法**：

```java
.authorizeHttpRequests(auth -> auth
        .shouldFilterAllDispatcherTypes(false)   // 只对 REQUEST 分发鉴权
        ...)
```

## 五、会话持久化

### 17. 刷新/切页后问答历史全丢

- **现象**：每次进 `/chat` 都像"新页面"
- **根因**：
  - `Chat.vue` 的 `sessions` 只是**组件内 `ref`**，离开组件即销毁，且 `onMounted` **无条件** `newSession()`
  - `kb` store 的 `currentKbId` **未持久化**，刷新归零 → 会话存储 key 对不上
- **解法**：
  - `Chat.vue`：按「用户 + 知识库」维度存 localStorage，挂载时优先恢复
  - `kb.ts`：持久化 `currentKbId` / `currentKbName`
