# 05 · 本地启动与端到端验证

## 前置依赖

| 依赖 | 版本 | 用途 |
|---|---|---|
| JDK | 17 | 编译运行后端 |
| Maven | 3.9+ | 打包 |
| Node.js | 18+ | 前端 |
| Docker | 任意 | 跑 PostgreSQL(pgvector) |
| Ollama | 本机 `11434` | 本地模型 |

Ollama 需已拉取模型：

```bash
ollama pull qwen3:4b
ollama pull qwen3-embedding:4b
ollama list        # 确认两个模型都在
```

## 启动步骤

```bash
# 1) 启动数据库（只需 Postgres，Ollama 用本机的）
docker compose up -d postgres
docker ps         # 确认 entrag-postgres-1 为 healthy

# 2) 构建并启动后端
build-backend.bat     # mvn clean package -DskipTests
run-backend.bat       # 带 DB / Ollama / CORS 环境变量启动 jar

# 3) 启动前端
cd frontend
npm run dev
```

访问 http://localhost:5173 ，账号 `admin` / `admin123`。

### 环境变量（`run-backend.bat` 内已设置）

```
DB_HOST=localhost  DB_PORT=5432  DB_NAME=enterprise_rag
DB_USER=rag        DB_PASSWORD=rag123456
OLLAMA_BASE_URL=http://localhost:11434
RAG_CORS_ALLOWED_ORIGINS=http://localhost:5173,http://127.0.0.1:5173
```

> ⚠️ `RAG_CORS_ALLOWED_ORIGINS` **不能用 `*`**：与 `allowCredentials(true)` 组合会让 Spring 抛异常，
> 导致带 `Origin` 头的浏览器请求全部 500。详见 [04-踩坑与排障](./04-踩坑与排障.md) 第 11 条。

## 端到端验证（命令行版）

用带 `Origin` 头的方式验证登录（模拟浏览器），再跑完整链路：

```powershell
$login = @{username="admin";password="admin123"} | ConvertTo-Json
$tok = (Invoke-RestMethod -Uri http://localhost:8080/api/auth/login `
        -Method Post -ContentType "application/json" -Body $login).data.token

# 建库
$kb = Invoke-RestMethod -Uri http://localhost:8080/api/kb -Method Post `
      -ContentType "application/json" -Headers @{Authorization="Bearer $tok"} `
      -Body '{"name":"DemoKB","description":"e2e","embeddingModel":"qwen3-embedding:4b"}'

# 上传（multipart 用 curl.exe，PS5.1 无 -Form）
curl.exe -s -X POST "http://localhost:8080/api/kb/$($kb.data.id)/docs" `
  -H "Authorization: Bearer $tok" -F "file=@c:\pycharmwork\EntRAG\demo_doc.md"

# 轮询入库状态（拿到 taskId 后）
curl.exe -s "http://localhost:8080/api/kb/ingest/status/{taskId}" -H "Authorization: Bearer $tok"

# 问答（SSE，带时间戳看是否真流式）
curl.exe -N -s "http://localhost:8080/api/kb/$($kb.data.id)/chat?question=%E5%B9%B4%E5%81%87" `
  -H "Authorization: Bearer $tok" | ForEach-Object {
      Write-Host ("{0} | {1}" -f (Get-Date -Format 'HH:mm:ss.fff'), $_) }
```

预期：

- 入库状态最终为 `DONE`，`embeddedChunks` = `totalChunks`
- 问答先返回 `event:references`，随后 `data:"..."` 逐条 token，时间戳逐步递增

## 常见现象与含义

| 现象 | 含义 |
|---|---|
| 上传后状态一直 `FAILED` | 查 `doc_meta.error` 字段；若只有 SQL 文本，去查 Postgres 容器日志 |
| 提问后等几秒才出字 | Ollama 冷启动（首次约 4s），第二次即秒出 |
| 答案里夹着推理过程 | 未关闭思考；确认 `ChatServiceImpl` 的 system 提示末尾有 `<arg_key:6124c78e>` |
| 浏览器报"网络请求失败" | 多半是后端 500 且响应体无 `message`；查 `backend_run.log` |
| 历史对话刷新后没了 | 检查 `kb` store 与 `Chat.vue` 的 localStorage 持久化 |

## 常用排查命令

```bash
# 后端日志
type backend_run.log           # 或 Get-Content ... -Tail 50

# 数据库服务端日志（INSERT 报错的真实原因在这里）
docker logs entrag-postgres-1 --tail 50

# 看向量表结构与数据量
docker exec entrag-postgres-1 psql -U rag -d enterprise_rag \
  -c "SELECT column_name, data_type FROM information_schema.columns WHERE table_name='vector_store';"
docker exec entrag-postgres-1 psql -U rag -d enterprise_rag -c "SELECT count(*) FROM vector_store;"
```

## 一键重置（需要时）

```bash
docker exec entrag-postgres-1 psql -U rag -d enterprise_rag -c "DROP TABLE IF EXISTS vector_store;"
# 重启后端后由 PgVectorStore 依据配置自动重建
```
